## 开发约束

1）组件设计：严格遵循单一职责原则，组件具有良好的可复用性和可维护性。

2）组件风格：必须使用函数组件，不要使用 Class Component。

3）状态与逻辑：优先使用 React Hooks，例如 useState、useEffect、useMemo、useCallback 等。

4）样式规范：使用原生 CSS 实现响应式设计，支持桌面端、平板端、移动端的响应式适配。

5）代码质量：代码简洁易读，避免过度注释，优先保证功能完整和样式美观。

6）禁止使用任何状态管理库、类型校验库、代码格式化库。

7）禁止使用 UI 组件库，例如 Ant Design、Element Plus、Material UI、Tailwind CSS 等。

8）将可运行作为项目生成的第一要义，尽量用最简单的方式满足需求，避免使用复杂的技术或代码逻辑。

9）不要引入后端接口，所有数据使用前端模拟数据完成展示。

10）不要使用 TypeScript，统一使用 JavaScript 和 JSX。

## 参考配置

1）vite.config.js 必须配置 base 路径以支持子路径部署，需要支持通过 @ 引入文件，不要配置端口号。

vite.config.js 参考：

import { defineConfig } from 'vite'
import react from '@vitejs/plugin-react'
import { fileURLToPath, URL } from 'node:url'

export default defineConfig({
  base: './',
  plugins: [react()],
  resolve: {
    alias: {
      '@': fileURLToPath(new URL('./src', import.meta.url))
    }
  }
})

2）index.html 必须包含 React 入口脚本，否则 Vite build 可能成功但页面空白。

index.html 参考：

<!DOCTYPE html>
<html lang="zh-CN">
  <head>
    <meta charset="UTF-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <title>React App</title>
  </head>
  <body>
    <div id="root"></div>
    <script type="module" src="/src/main.jsx"></script>
  </body>
</html>

3）路由配置必须使用 HashRouter，避免服务器端路由配置问题。

src/router/index.jsx 参考：

import { createHashRouter } from 'react-router-dom'
import Home from '@/pages/Home.jsx'

const router = createHashRouter([
  {
    path: '/',
    element: <Home />
  }
])

export default router

4）src/main.jsx 参考：

import React from 'react'
import ReactDOM from 'react-dom/client'
import { RouterProvider } from 'react-router-dom'
import router from './router'
import './styles/global.css'

ReactDOM.createRoot(document.getElementById('root')).render(
  <React.StrictMode>
    <RouterProvider router={router} />
  </React.StrictMode>
)

5）package.json 文件参考：

{
  "scripts": {
    "dev": "vite",
    "build": "vite build"
  },
  "dependencies": {
    "@vitejs/plugin-react": "^4.2.1",
    "vite": "^5.0.0",
    "react": "^18.2.0",
    "react-dom": "^18.2.0",
    "react-router-dom": "^6.22.0"
  },
  "devDependencies": {}
}

## 网站内容要求

- 基础布局：各个页面统一布局，必须有导航栏，尤其是主页内容必须丰富。
- 页面结构：根据用户需求合理拆分页面，例如首页、列表页、详情页、关于页等。
- 组件拆分：根据页面内容合理拆分组件，例如 Header、Footer、Card、Section、Banner 等。
- 文本内容：使用真实、有意义的中文内容，不要使用 lorem ipsum。
- 图片资源：可以使用 https://picsum.photos 服务或其他可靠的占位符。
- 示例数据：提供真实场景的模拟数据，便于演示。
- 视觉效果：页面需要具备良好的视觉层次、间距、配色和响应式体验。
- 交互效果：可以添加基础交互，例如 tab 切换、筛选、展开收起、按钮点击反馈等，但不要过度复杂。

## 质量检验标准

确保生成的项目能够：

1. 通过 npm install 成功安装所有依赖。
2. 通过 npm run dev 启动开发服务器并正常运行。
3. 通过 npm run build 成功构建生产版本。
4. 构建后的项目能够在任意子路径下正常部署和访问。

6. 所有路由在刷新后不会出现 404。
7. 所有组件引用路径正确，不存在文件缺失问题。
8. 所有 CSS、JSX 语法正确，不产生构建错误。
9. src/router/index.jsx 中 import 的每个页面组件必须创建对应文件；不要引用未创建的页面，例如导入 '@/pages/ProjectDetail' 时必须写入 src/pages/ProjectDetail.jsx。
